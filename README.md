# kakeibo

スマートフォンでの利用を中心にした、チャットとレポートの2画面の家計簿です。既存のReact/Viteアプリを引き継いでいます。

## 起動と検証

Node.js 22以上、pnpmを使用します。

```sh
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
pnpm test
pnpm build
```

AIの認証情報がなくても、文字の簡単入力（例：`ランチ 1,200円`）、手入力、修正・取り消し、レポート、カテゴリ編集、定期登録、バックアップを使用できます。画像の自動読取と自由なAI相談は実接続が必要です。未接続時に読み取り成功のデモを実データとして登録しません。

## 背景とデザイン

添付の水彩画像を初期背景にしています。設定の「自分らしい背景に」から画像の変更、暗さの調整、初期背景へのリセットができます。背景はIndexedDB、表示設定は`kakeibo_appearance_v1`に保存します。端末・ブラウザごとの設定で、台帳のバックアップやAIへの送信には含めません。

文字と数値は、半透明の明るい面の上に濃い色で表示します。背景画像の色や明るさが変わっても読めるよう、ボタン・入力欄・レポートのガラス面には最低限の白い濃度を残します。

## OpenAIとfreeeの接続

`.env.example`を`.env.local`にコピーします。本番では、対象のVercelプロジェクトのEnvironment Variablesに同じ項目を設定します。秘密情報はGitHubやチャットに貼らず、サーバー環境変数にのみ保存してください。`VITE_`を付けると公開されるため使用しません。

| 環境変数 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI Responses API、画像入力、Structured Outputs |
| `OPENAI_MODEL` | 初期値は画像入力・構造化出力に対応する`gpt-5-mini`。利用可能なモデルに変更可能 |
| `APP_ACCESS_CODE` | 個人用のAPI接続コード。ランダムな24文字以上。アプリの設定画面で入力 |
| `SESSION_SECRET` | セッションとfreee認証Cookieの暗号化に使う、独立したランダムな32文字以上 |
| `FREEE_CLIENT_ID` / `FREEE_CLIENT_SECRET` | freeeアプリのOAuth認証設定 |
| `FREEE_REDIRECT_URI` | `https://実際の公開ドメイン/api/freee/callback`。freee側のコールバック設定と完全一致させる |
| `FREEE_COMPANY_ID` | 認証結果に事業所IDが含まれない場合のみ設定 |

freeeアプリは請求書の読み取りを許可する設定で作成し、OAuthコールバックURLを登録します。アプリの設定から接続用コードを入力し、続いて「freee請求書を連携」を押して、本人がfreee側で事業所選択と認可を完了します。freeeのデータを変更するAPIは呼び出しません。

OpenAIへ送るのは、利用者が送信した写真・会話、指定カテゴリ、直近30件までの記録と必要な集計値です。レポートの分析時は集計値を送ります。Responses APIには`store:false`を指定しています。これはOpenAIの全保存ポリシーを無効にする指定ではありません。

## 記録と確認

- カメラボタンはスマートフォンの背面カメラを優先する写真入力を開きます。端末・ブラウザによってはファイル選択が表示されます。＋ボタンからスクリーンショットを添付できます。
- 写真は送信前にチャットの入力欄でプレビューできます。1回に2枚まで、最大1600pxへ圧縮します。HEIC等をブラウザがデコードできない場合はJPEG/PNGに変換して添付してください。
- 明瞭な単一支出レシートでカテゴリ・金額・日付が検証を通った場合のみ自動登録します。モデルの確信度も補助条件にしますが、正確性の保証には使用しません。
- 不明瞭な画像、複数画像、収入画像、修正、重複候補は確認カードで内容を確定します。AIは直接台帳を更新しません。
- 同一画像、請求書番号、同日・同額・同内容の記録を照合します。番号を読めない収入画像とfreeeの照合は完全ではありません。同月にfreee収入がある場合は、追加時に別収入であることを確認します。
- 定期登録はアプリを開いた際に、選択中の月の不足分を作成します。閉じている間に動くジョブではありません。31日を設定した場合、日数の少ない月は月末にします。

## 収入の定義

利用者指定により、**当月の請求額を収入**にします。`GET https://api.freee.co.jp/iv/invoices`の`start_billing_date`と`end_billing_date`で当月を取得します。請求書の`billing_date`で計上し、入金日・入金期日・入金済み状態は月判定に使用しません。

金額はfreeeの`total_amount`から`amount_brought_forward`（前月等からの繰越残高）を除いたものです。源泉徴収がある場合はfreeeの合計金額に従います。取消済み請求書を除外し、全ページの取得が完了してから置き換えます。失敗時は既存の記録を維持します。負の請求額は部分反映せず確認を求めます。

アプリを開いたとき・レポートの月を切り替えたとき、前回同期から15分以上経過していれば同期します。手動更新も可能です。同じ請求書IDは更新し、同じ番号の収入スクリーンショットを置き換えます。freee由来の金額編集はfreee側で行います。

収支と貯蓄率は請求額を基準にした指標で、預金残高とは異なります。

## 保存と移行

- 既存の`kakeibo_records` / `kakeibo_categories`を維持します。カスタムカテゴリも引き継ぎます。新規利用者にサンプル数字を自動投入しません。
- 初回更新前のデータを`kakeibo_before_chat_v1`へ退避します。読み取れない既存データは自動で上書きせず編集を止めます。
- チャットは`kakeibo_chat_v1`、定期登録は`kakeibo_recurring_v1`、写真はIndexedDBに保存します。クラウドへの家計簿同期や複数人での共有は含みません。
- **localStorageとIndexedDBは端末・ブラウザ・URLごとに別です。** 別ドメインへ移すときは、元のURLでバックアップを保存してから新しいURLで読み込んでください。旧版にエクスポート機能がない場合は、同じ公開ドメインで今回の更新を適用してから保存します。
- バックアップJSONは記録、カテゴリ、定期登録、関連写真を含みます。チャット履歴とAPI認証情報は含みません。読み込みは50MBまでです。復元時は現在の値を`kakeibo_before_restore`に退避します。
- freee同期直前の記録は`kakeibo_before_freee_sync`にも保持します。ブラウザデータの消去やストレージ障害は、これらの端末内バックアップも失わせるため、定期的なダウンロードが必要です。

## 公開

Vercelの既存プロジェクトへこのリポジトリのブランチを接続します。`vercel.json`はViteの静的配信と`api/[...path].js`のNode.js Functionsを使用します。通常のVite静的ホストだけではAI/freee APIは動きません。プレビュー用URLで試す場合は、そのURLもfreee側のコールバック許可に合わせてください。

本実装は単独利用を前提とします。接続コードでサーバーAPIを保護し、CookieにはAES-256-GCM・HttpOnly・SameSite=Lax、本番ではSecureを使用します。セッションは7日、freee Cookieは最大90日です。アクセストークン期限前の更新時に新しいリフレッシュトークンも保存します。ブラウザ間の同時再認証やトークン失効時は再連携が必要です。

実アカウントでの画像読み取り、OAuth、請求額の照合、実機カメラ、バックアップ移行を確認してから本番ブランチへ取り込んでください。

参照した公式仕様：[OpenAI画像入力](https://developers.openai.com/api/docs/guides/images-vision)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[freee請求書API](https://developer.freee.co.jp/reference/iv)、[freee OAuth](https://developer.freee.co.jp/reference/%E8%AA%8D%E5%8F%AF%E3%82%B3%E3%83%BC%E3%83%89)。
